# 黑马点评响应式网页改版设计

日期：2026-09-19

## 1. 目标

将 `D:\code\nginx-1.18.0\html\hmdp` 中现有的手机端多页面前端改造成电脑端优先、同时兼容手机的响应式网站。

改版保留现有业务功能、Java API、登录 token、Vue 2、Element UI、Axios 和 Nginx 静态托管方式。项目不引入 Node 构建流程，不迁移到新的前端框架，也不修改后端接口协议。

成功标准：用户在电脑端获得完整的桌面导航和多栏布局，在手机端获得可正常操作的单栏布局和底部导航；智能问答成为网站的正式功能。

## 2. 已选方案

采用“改造现有 Vue 2 多页面前端”方案。

未采用以下方案：

- Vue 3 单页应用重写：需要重新搭建路由、构建和部署，范围过大。
- 仅追加桌面 CSS：现有手机页面结构难以形成自然的桌面信息层级。

改造会调整页面 HTML 结构与 CSS，并抽取公共 Vue 组件。现有接口调用逻辑能复用时直接保留。

## 3. 信息架构

### 3.1 桌面导航

桌面端统一显示固定顶部导航：

```text
Logo | 首页 | 店铺分类 | 发布笔记 | 智能问答 | 搜索 | 用户中心
```

导航行为：

- Logo 和“首页”进入 `/`。
- “店铺分类”进入店铺列表，并保留当前类型筛选能力。
- “发布笔记”进入 `/blog-edit.html`。
- “智能问答”进入 `/rag.html`。
- 搜索框搜索店铺名称或地点，结果进入店铺列表。
- 用户中心显示登录入口或用户头像，进入 `/info.html`。

### 3.2 手机导航

宽度小于 `768px` 时隐藏完整顶部导航，保留紧凑页头和底部导航。底部导航包含首页、店铺、发布、智能问答和我的。

### 3.3 内容容器

桌面内容最大宽度为 `1200px`，在页面中水平居中。桌面页面允许双栏或卡片网格；手机页面全部变为单栏。

## 4. 视觉规范

- 品牌主色：`#ff6633`。
- 页面背景：`#f6f7f9`。
- 卡片背景：白色。
- 卡片样式：8～12px 圆角、细边框或轻阴影。
- 字体：系统字体、微软雅黑及现有中文回退字体。
- 正文颜色：`#303133`；次要文字：`#909399`。
- 按钮、链接和选中状态统一使用品牌橙色。
- 卡片悬停只在支持鼠标的设备启用，使用轻微上移和阴影变化。
- 表单、加载状态、空状态和错误提示使用统一样式。

## 5. 响应式规则

### 5.1 桌面：宽度不小于 1024px

- 显示完整顶部导航。
- 隐藏手机底部导航。
- 使用两栏、三栏或卡片网格布局。
- 页面内容限制在 `1200px` 内。

### 5.2 平板：768px～1023px

- 顶部导航使用紧凑间距。
- 三栏网格降为两栏。
- 侧栏缩窄，必要时移到主内容下方。

### 5.3 手机：小于 768px

- 隐藏桌面导航，显示手机页头和底部导航。
- 所有布局变为单栏。
- 内容使用全宽卡片，减小外边距与内边距。
- 表单按钮保持足够触控高度。
- 页面为底部导航预留空间。

## 6. 页面设计

### 6.1 首页 `index.html`

- 顶部导航下显示搜索和品牌引导区。
- 主区域左侧显示店铺分类和探店内容流。
- 右侧显示热门店铺、热门笔记或登录提示。
- 手机端按“搜索、分类、内容流”的顺序单栏排列。

### 6.2 店铺列表 `shop-list.html`

- 桌面左侧提供类型和条件筛选。
- 右侧使用两到三列店铺卡片网格。
- 店铺卡片展示首图、名称、评分、商圈、人均价格和地址摘要。
- 手机端使用单列列表，筛选区折叠。

### 6.3 店铺详情 `shop-detail.html`

- 左侧主栏展示店铺图片、评分、地址、介绍和评价。
- 右侧固定信息卡展示营业时间、价格、优惠券和操作入口。
- 增加“询问 AI”按钮，跳转到 `/rag.html?shopId=<当前店铺ID>`。
- 手机端按店铺信息、操作、优惠券、评价顺序排列。

### 6.4 笔记详情 `blog-detail.html`

- 主栏展示图片、标题和正文。
- 侧栏展示作者、点赞信息及相关推荐。
- 手机端作者信息放在正文前，相关推荐放在正文后。

### 6.5 发布笔记 `blog-edit.html`

- 使用居中的桌面表单卡片。
- 标题、正文、店铺选择、图片上传分组显示。
- 手机端表单改为全宽并保持现有发布接口。

### 6.6 登录 `login.html`、`login2.html`

- 桌面端使用品牌介绍与登录表单双栏布局。
- 手机端只显示紧凑登录卡片。
- 保留验证码、token 保存和跳转行为。

### 6.7 个人页面 `info.html`、`other-info.html`

- 左侧展示头像、昵称、简介和操作按钮。
- 右侧使用标签页展示笔记、评价、粉丝和关注。
- 手机端恢复头像信息在上、标签页在下的单栏结构。

### 6.8 编辑资料 `info-edit.html`

- 使用统一表单卡片、字段说明和操作按钮。
- 保留现有用户资料接口。

### 6.9 智能问答 `rag.html`

- 桌面左侧为上传与文档管理，右侧为问答区。
- 问答区展示问题、回答、加载状态和参考来源。
- 文档区支持上传、状态刷新和删除。
- 手机端以“问一问”和“知识文档”标签页切换。
- 浏览器只调用 Java `/api`，不直接访问 Python `8003`。

## 7. 公共组件与文件

新增或整理以下公共文件：

```text
html/hmdp/
├─ css/
│  ├─ desktop.css
│  ├─ components.css
│  └─ 各业务页面 CSS
├─ js/
│  ├─ header.js
│  ├─ footer.js
│  └─ common.js
└─ 各业务 HTML 页面
```

- `header.js`：桌面导航、搜索、登录状态和移动端紧凑页头。
- `footer.js`：手机底部导航；桌面端通过媒体查询隐藏。
- `desktop.css`：容器、栅格、断点和页面骨架。
- `components.css`：按钮、卡片、状态、空内容和通用表单样式。
- 各业务 CSS：只保存该页面特有的布局。

公共样式类使用 `hmdp-` 前缀，减少与 Element UI 和现有页面样式冲突。

## 8. 数据流

```text
浏览器 → Nginx :8080 → /api → Java :8081
                            ↓
                       shop-qa :8003
                            ↓
                    Milvus / 大模型
```

- 店铺、用户、优惠券和笔记继续通过 `/api/*` 调用 Java。
- 文档上传和全站问答通过 `/api/rag/*` 调用 Java。
- 店铺问答通过 `/api/shop/{shopId}/ask` 调用 Java。
- Axios 继续从 `sessionStorage` 读取 token，并放入 `authorization` 请求头。
- Java 从 token 获取用户身份，前端不提交 `owner_id`。

## 9. 状态与错误处理

- 请求进行中禁用重复提交并显示加载状态。
- 空列表显示统一空状态，不展示空白区域。
- 未登录访问受保护操作时提示并跳转登录页。
- API 失败时显示 Java 返回的错误信息；网络错误显示“服务暂不可用”。
- 图片加载失败时使用现有默认图片。
- RAG 请求使用独立的较长超时时间，普通接口继续使用默认超时。
- 文档处于 `pending` 或 `processing` 时定时刷新，完成或失败后停止轮询。

## 10. 实施边界

本次包含：

- 全部现有业务页面的桌面布局和手机响应式改造。
- 公共顶部导航、手机底部导航和统一视觉组件。
- 店铺详情的智能问答入口。
- 智能问答页面桌面双栏改造。
- 现有前端交互在新布局中的适配和验证。

本次不包含：

- Vue 3、React 或其他框架迁移。
- 新增 Node、npm 或打包部署流程。
- Java、Python RAG 或数据库接口重构。
- 新的地图、支付、即时消息等业务功能。
- 重新制作店铺和笔记业务数据。

## 11. 验收标准

### 11.1 页面与导航

- 所有 HTML 页面通过 Nginx 正常返回。
- 桌面顶部导航和手机底部导航链接有效。
- 当前页面具有明确的选中状态。
- 店铺详情“询问 AI”携带正确店铺 ID。

### 11.2 布局

- `1366×768` 和 `1920×1080` 下没有页面级横向滚动。
- `375×812` 下内容不溢出，主要操作可触达。
- 桌面多栏在手机端正确变为单栏。
- 导航不会遮挡页面主要内容。

### 11.3 功能

- 登录、店铺列表、店铺详情、笔记详情、发布笔记、个人中心和资料编辑继续调用原接口。
- 智能问答可以上传文档、查看状态、删除文档、按店铺提问和显示来源。
- token 继续通过现有 Axios 拦截器发送。
- Java 和 Python 服务不需要修改接口即可支持新页面。

### 11.4 验证

- `nginx -t` 配置检查通过。
- 所有内嵌 JavaScript 通过语法检查。
- 自动检查所有本地 CSS、JavaScript、图片和页面链接不存在缺失文件。
- 关键页面在桌面和手机视口完成浏览器截图检查。
- 启动 Java 与 RAG 后，对登录、店铺详情、上传和问答完成一次人工流程验证。

## 12. 风险控制

- 先建立公共布局与组件，再逐页迁移，避免各页面样式继续分叉。
- 每迁移一个页面就检查桌面和手机视口，避免最后集中修复响应式问题。
- 保留原接口调用代码，页面结构调整与业务行为调整分开进行。
- 使用明确的 CSS 前缀和加载顺序，控制旧样式覆盖问题。
- 在全部页面验收完成前保留可对照的原始 Git 版本。
